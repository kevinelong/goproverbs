# Autonomous research plan - September 21, 2026

Objective: improve and understand goproverbs through controlled experiments,
while keeping an explainable, independently checked Go implementation.

Authorization: the user requested a written plan for all nine workstreams and
autonomous execution with reasonable assumptions. Routine implementation,
downloads, local tests, and packaging are in scope. Preserve historical results.
No default strength promotion without evidence. Do not describe generated
positions or machine judgments as expert-reviewed. Publication is a separate
release step; first make a reviewable local package.

## Assumptions and experimental contract

- Target strategic play on 19x19 under Tromp-Taylor, komi 7.5, paired colors.
- Small boards remain useful for exact correctness and local tactical tests.
- Keep the old b10 KataGo weights fixed for the main algorithm comparisons.
- Include neural inference in the decision budget. Report actual wall time,
  completed depth, fallback use, illegal moves, unfinished games, and resources.
- One neural inference workload at a time. Inspect runner locks, Ollama, GPU
  processes and VRAM; unload identified idle models only; release models after.
- Initial smoke comparisons precede larger runs. Prefer fixing a failed
  mechanism over accumulating many games of a demonstrably broken variant.
- Freeze opening sets and parameters before matches; do not tune on confirmation
  games. Existing fixtures and games are development data, not pristine holdout.

## Execution order

1. Freeze baseline and add SGF/corpus infrastructure (1, 2).
2. Implement and test neural nomination first, then the evaluator hook (3, 4).
3. Run the four-way ablation on development positions and paired games. Record
   failures and costs. Start at 200 ms; use 1000 ms when completed-depth evidence
   shows that the neural evaluator cannot complete a meaningful round at 200 ms.
4. Profile actual bottlenecks and add catalog/safety diagnostics (5, 6, 7).
5. Test CPU and a newer network as separate variables (8).
6. Finish terminal controls, timing and a local release bundle; consolidate
   conclusions, results, and open questions (9).

## Scale-up gates

- Smoke: unit/protocol tests plus 2 opening pairs per new mechanism.
- Screening: up to 20 opening pairs per promising variant, initially 200 ms.
- Confirmation: at least 50 independently selected opening pairs for a finalist,
  with paired uncertainty estimates. No Elo claim without a suitable calibrated
  opponent pool. Finite samples remain conditional on openings and hardware.
- Expert-reviewed positions, comprehensive life/death, and a general tournament
  rating are long-term deliverables, not boxes to mark complete from smoke tests.
