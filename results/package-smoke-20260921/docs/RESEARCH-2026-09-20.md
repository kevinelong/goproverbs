# Search, scoring, and tuning research - 2026-09-20

## Recommendation

Use the baseline weights with bounded search, CPU only. Keep tuned and modern
profiles opt-in. Search improved the controlled full-game comparison, while
fixture tuning did not improve the acceptance scores. No rating or competitive
strength claim follows from these small experiments.

The implementation follows the three accepted decisions: aim for explainable
strength, let bounded tactical reading override soft proverbs, and support both
editable defaults and separately saved learned weights.

## Delivered

- Selective iterative-deepening negamax with alpha-beta pruning, alternating
  plies, node/time/depth/beam budgets, and legal completed-iteration fallback.
- Search explanations with the selected line, signed leaf features, edge
  preferences, and immediate proverb-inspired move contributions.
- Tromp-Taylor positional superko, multi-stone suicide, area scoring, terminal
  results, and corresponding SGF output. CLI/GTP executable default to this
  policy; the original library default remains simple ko/no suicide.
- Strict editable weight files; CLI and GTP load/save controls; separate baseline,
  modern, and automatically tuned profiles.
- CPU-only Python fixture tuning, evaluation, and paired-color match harness.
- Independent Python legality/board/scoring referee, SGF game records, decision
  traces, input hashes, and a source manifest.

See [standards](STANDARDS.md) for the primary
[Tromp-Taylor source](https://tromp.github.io/go.html) and
[GTP specification](https://www.lysator.liu.se/~gunnar/gtp/gtp2-spec-draft2.pdf).
The [heuristic catalog](HEURISTICS.md) distinguishes sourced teaching principles
from our numerical proxies and unimplemented pattern ideas.

## Fixture evidence

Final release, 1,000 ms / 5,000 nodes / depth 3 / beam 12:

| Profile and decision method | Training cases | Other development cases |
| --- | ---: | ---: |
| Baseline one-move policy | 6/6 | 4/5 |
| Baseline search | 5/6 | 4/5 |
| Tuned one-move policy | 6/6 | 4/5 |
| Tuned search | 5/6 | 4/5 |

All fixture searches completed depth 3. Search avoided the generated snapback
trap: the immediate policy played C1, allowing a larger recapture at D1;
search chose A4. The fixture rejects C1 without claiming A4 is proven optimal.

Search missed the expected immediate move in `rescue-single` and
`capture-corner-pair`. Its continuation deferred the rescue/capture while the
opponent also played elsewhere. The current evaluator and limited horizon can
misjudge urgency; an atari penalty can also make leaving threatened enemy
stones on the board too attractive. These failures remain visible in reports.
The acceptance labels express intended local behavior, not professional proof
of a unique whole-board best move.

The original `rescue-edge-pair` label accepted only A4. Review showed that B1
captures White A1 and gives the Black pair two liberties, so B1 was added.
The independent release test verifies that correction. Original reports remain
in `results/`; v2 and final reports use the corrected label. These cases have
been inspected during development and must not be called a pristine holdout.
The tuner reads only the six training cases and does not optimize on the five
other cases.

## Weight tuning

Deterministic bounded coordinate descent optimizes training-case acceptance
plus capped good-versus-bad move margins, with a penalty for moving away from
the starting profile. It tunes move preferences only, not search leaf weights.

| Weight | Baseline | Tuned |
| --- | ---: | ---: |
| save_atari | 10 | 14.25 |
| empty_corner | 2 | 3 |
| side_development | 0.5 | 0 |

All other weights are unchanged. The training objective increased from
1.200333 to 1.249719; classification scores did not improve. The improvement
is in the optimization objective, not demonstrated playing strength.
See [tuning provenance](../profiles/tuned.tuning.json).

Final release, seed 20260920, three two-move openings, each played with colors
swapped. Search budget: 1,000 ms, 2,000 nodes, depth 3, beam 12. Komi 0.5.
Opponent: the same profile's immediate one-move policy. Move cap: four times
board area; unfinished games would be reported separately.

| Experiment | Search wins / completed | Unfinished | Median search round trip |
| --- | ---: | ---: | ---: |
| Baseline, 5x5 | 6/6 | 0 | below timer resolution |
| Baseline, 9x9 | 6/6 | 0 | 31 ms |

The independent referee checked every generated move, resulting board, and
final score. There were no discrepancies. Timing includes GTP communication
and trace retrieval; Windows monotonic-clock measurements here are coarse.
This comparison supports search over the immediate policy in this controlled
setting. Both profiles won against their own weak one-move opponent; this does
not establish that tuned search is better than baseline search.

All experiments here use CPU code and no inference server or GPU allocation.
No unrelated application or model process needed to be terminated.

## Next priorities

1. Add bounded tactical extensions at unstable leaves, with carefully labeled
   capture/rescue/sacrifice positions. Revisit material versus atari penalties.
2. Build a larger expert-reviewed SGF position set, separating by source/game
   before tuning. The present eleven cases are a development suite.
3. Compare baseline and tuned search directly, then evaluate against an external
   established GTP engine. Use enough varied paired games for useful uncertainty
   estimates and run feature ablations.
4. Implement hane, peep, and knight-cut patterns only with explicit applicability
   checks and counterexamples. The current cut-pressure proxy is disabled.
5. Add SGF import, stronger life/death and endgame handling, and controller time
   management before claiming broad GUI/tournament interoperability.

Selective search cannot prove life, solve arbitrary ladders, or guarantee best
play. There is no neural model, established rank, dead-stone adjudicator, or
complete encoding of the classical proverb literature. The current result is
an inspectable research engine with reproducible evidence and explicit gaps.
